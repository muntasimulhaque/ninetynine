The bottom bar as a floating squircle

Three readings of the same bar — today's quiet footer, Apple's floating squircle, and a flat middle path — each rendered with the app's real palette and type register. The tab grammar (filled glyph + semibold small-caps + emerald tint) is identical in all three; only the vessel changes.

Corners use corner-shape: superellipse(4) where the browser supports it — the same curve family as the app's SquircleShape — falling back to plain radii elsewhere. Arabic here is system-set, not HAFS; treat it as position-holding.

The flat squircle

Same vessel, no shadow — lifted by one tonal step and a hairline border. The squircle shape with the book's stillness.

How it's built (Variant B)

No new dependencies. The bar already lives in QuietBottomBar (MainActivity.kt) — it changes container, not behavior. Selection grammar, Role.Tab, 60dp targets, selectableGroup, re-tap-to-top, the wide-screen barMeasure() cap: all unchanged.

// PageParts.kt gains one token beside large/medium:
val AppShapes = Shapes(
    medium = SquircleShape(20.dp),
    large = SquircleShape(28.dp),
)

// MainActivity.kt — QuietBottomBar becomes:
Box(
    Modifier.fillMaxWidth()
        .navigationBarsPadding()          // floats above the gesture strip
        .padding(horizontal = 14.dp, vertical = 10.dp)
) {
    Surface(
        shape = SquircleShape(26.dp),     // n = 4, the house exponent
        color = MaterialTheme.colorScheme.surfaceContainer,
        shadowElevation = 6.dp,
    ) {
        Row(
            Modifier.barMeasure()         // still capped on tablets
                .selectableGroup()
                .heightIn(min = 60.dp)
        ) { /* tabs unchanged */ }
    }
}

The shadow is the only risky note. Android's elevation shadow is directional and can read smudgy on flat paper. Two fallbacks, in order: tune ambientColor/spotColor (API 28+; below that it degrades to the standard shadow, acceptable); or hand-draw a soft halo in drawBehind with a blurred Paint (~15 lines, exact control). The mockup's shadow (2/20/40dp steps at 6–14% ink) is the target look either way.

Dark and AMOLED: the shadow disappears on black, so the vessel needs a 0.5dp outlineVariant border (as Variant C already wears) or a step up to surfaceContainerHigh. Same rule the share sheet already lives by.

Scroll-under vs padded: the mockup shows content scrolling under with a fade scrim — Apple's move. The quieter alternative is Scaffold clearance (content never goes under). Scroll-under costs a scrim layer and a nested-scroll decision (the exact class of thing that bit the share sheet); padded costs nothing and keeps the book's stillness. Both work; padded is my default recommendation for a first ship.

What each one says

Variant A

Keep the quiet footer

  • Book-binding register: the bar is of the page
  • Zero new visual systems; nothing to reconcile
  • The hairline rule is already WCAG-clean
The purist choice — but it leaves the squircle work confined to cards and menus.
Variant B

Floating squircle, shadowed

  • The iOS-familiar vessel; reads instantly as "polished app"
  • Content-under-scroll adds depth the paper app currently doesn't have
  • Shadow needs dark-theme compensation; scroll-under needs care
The statement piece. Biggest departure from the quiet-book grammar — and the biggest visual dividend.
Variant C

Flat floating squircle

  • Squircle shape + tonal lift only; stillness preserved
  • Trivially safe in all three themes (border, not shadow)
  • Floating without depth can read slightly undecided on paper
The safe middle: modern shape, book manners. Weakest at communicating "this floats".

Every frame above uses the app's literal palette values. If you pick a variant, the implementation is the Surface swap above plus the shadow work — everything else in the bar stays as it ships today.
